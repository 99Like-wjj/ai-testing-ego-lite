# v0.2.2 HTML 报告性能优化

状态：开发与本轮自测完成，未发布、未进行用户真实报告验收。基线为 main `5bccc9c`（0.2.1），工作分支 `feat/v0.2.2-report-performance`，开发身份 `0.2.2-rc.1 / report-performance-1`。

## 核实与最终方案

外部分析提到的 `70657f8` 不在当前本地历史中；以下以实际基线源码与合成实验为准。未取得用户卡顿的原始报告，因此不能将合成结果当作该报告的诊断或耗时承诺。

1. **修复重复解析。** `ui-text.mts` 用 undefined 同时表示未初始化和未配置 presentation，每次取文案都会再次解析整个内嵌 JSON；报告入口还会额外解析。统一页面数据读取缓存，缺省中文、显式中文与外语均只解析一次；用例审阅页面同样使用这一读取能力。无效 JSON 仍明确报错。
2. **完整记录按需渲染。** 默认折叠的原始判断、全部动作和历史详情只在首次展开时生成；关闭再展开复用已生成 DOM。保留全部字段、证据 ID、来源、历史与业务四态，不能以优化删减证据。
3. **局部切换。** 缓存每个目标的步骤投影；切步骤仅更新当前步骤状态与右侧内容，切证据仅更新当前证据卡和标签。保留目录、概览、完整记录的 DOM、展开状态与滚动位置；刷新、深链接、前进后退仍能恢复选中项。
4. **分离截图交付。** inline 保持可独立打开的单 HTML；bundle 的图片数据通过受限相对附件地址交付，使用普通 img 按需加载，不通过 fetch，支持 file:// 离线。只开放图片所需 CSP，继续禁止业务网络请求、可执行附件和任意路径。原件哈希、缺失提示及事务回滚继续校验。inline 使用复用的 Blob 地址避免反复将 Base64 复制到 DOM，并释放图片查看器不再使用的引用。

独立缩略图暂不纳入本次实现：当前优先消除重复解析、隐藏区预生成和 DOM 重建。生成缩略图需要额外图片编解码运行依赖，且不能代替原件；本次先在真实浏览器检查上述改动后的图片加载与交互，再用测量结果决定后续收益。搜索索引与长对话分批渲染也不在本次范围内，不重写报告框架。

## 验收要求

- 10 步与 100 步合成报告，不提供 presentation、显式中文、英文均只解析页面主数据一次；进入目标与多次切步骤不增加该计数。
- 首次打开目标不生成完整记录正文；展开后字段可追溯，关闭重开不重建。切步骤不替换目录、目标概览、步骤列表或完整记录，切证据不替换右侧其余内容。
- inline 和 bundle 在真实浏览器离线打开；截图可看原尺寸、切换、缩放与关闭返回。损坏／缺失附件显示失败；安全路径白名单、CSP 与内容转义保持。
- bundle HTML 不携带普通截图 Base64 原图；复制完整目录仍能读图，原附件篡改能被 verify-report 检出。历史、测试附件、对话来源和报告的四态统计保持。
- 记录前后解析次数、DOM 数量、HTML 大小与交互实测，耗时只作为该机器的合成样本结果，不使用易抖动的毫秒阈值作为工程测试。
- 运行相关回归、typecheck、完整 npm test、check:public 和 git diff --check。不生成候选安装包、不安装用户 Skill、不合并 main、不创建 Tag/Release。

## 复现入口

先运行工程构建，再生成一个明确标记为合成数据的新报告目录：

```powershell
npm run build
$ReportPerfRoot = Join-Path $env:TEMP ('ego-report-performance-' + [guid]::NewGuid().ToString('N'))
node .build/node/tools/report-performance.mjs --output $ReportPerfRoot --steps 100
```

工具创建 inline／bundle 与默认中文／显式中文／英文六种组合，拒绝覆盖已有目录，输出每份 HTML 的实际位置和字节数。用浏览器打开相应 report.html，进入场景、切步骤与证据、展开完整记录并核对原图。主数据计数、DOM 复用、缺省语言、损坏数据和附件完整性的确定性回归在 `tests/report-performance.test.mts`，随 `npm test` 运行。
